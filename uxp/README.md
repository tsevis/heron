# Heron — Photoshop panel

Applies any Heron instrument to the active document and returns the result as an
**editable layer group**, not a flat pixel dump.

The panel is a frontend and nothing else. It talks HTTP to the local Heron
service and imports nothing from the engine — the engine stays UI-agnostic. Every
control it shows is described by the service (`/api/meta`), including the
per-instrument dial map in `webapp/dials.json`, so the panel and the web app read
one definition and cannot drift apart.

## Files

| File | Role |
|---|---|
| `manifest.json` | UXP manifest v5 — panel entrypoint, permissions, icons |
| `index.html` | markup + styles, using UXP's built-in `sp-*` Spectrum widgets |
| `main.js` | UI: service discovery, dials, request assembly, progress |
| `bridge.js` | everything touching the Photoshop DOM (export, place, group) |
| `icons/` | panel-tab icons, generated by `scripts/make_panel_icons.py` |

No bundler, no `node_modules`, no build step. UXP ships the Spectrum widgets, so
four files load directly.

## Install

Photoshop discovers plugins in its own `Plug-ins` folder. That folder is
root-owned, so this needs `sudo` once. A symlink is used rather than a copy so
edits to the repo are live:

```bash
sudo ln -s "$PWD/uxp" "/Applications/Adobe Photoshop 2026/Plug-ins/heron"
```

Restart Photoshop, then **Plugins → Heron**.

Developer Mode must be on for an unsigned plugin to load — the UXP Developer Tool
enables it, or create `/Library/Application Support/Adobe/UXP/Developer/settings.json`
containing `{"developer": true}`.

To uninstall: `sudo rm "/Applications/Adobe Photoshop 2026/Plug-ins/heron"`.

> `~/Library/Application Support/Adobe/UXP/extensions/` is **Adobe Bridge's**
> extension folder, not Photoshop's. Installing here does nothing for Photoshop.

## Use

Start the service (`./heron.sh`, port 8077). The panel finds it on load and keeps
retrying while it is down, so starting the service later is enough — no reload.

1. Pick a camera and preset. Dials you move off the preset turn orange.
2. **Render → layer stack.** The input is the flattened *visible* layers —
   hidden layers, including a previous Heron group's stages, contribute
   nothing. The panel states the scope under the button.
3. A group named `Heron — <camera>/<preset>` appears: composite visible on top,
   each physics stage and Radiance Graph channel below it, hidden. Unhide any of
   them to edit.

**Selection only** (default on) crops a throwaway duplicate to the marquee and
translates the returned layers onto those exact bounds. Your document is never
modified. With nothing selected it renders the whole canvas and says so.

**Seed** is always sent explicitly: same document + same dials + same seed gives
the same layers.

**Neural finish** is off by default and priced in the UI (~25–60 s per frame). It
arrives as a separate top layer named `neural finish`, above the group and never
merged into it — a diffusion output cannot be decomposed back into
emission/noise/palette, so folding it in would destroy the stack. The panel does
not take that placement on trust: it moves the layer above the group explicitly,
then checks the layer's parent and reports where it actually landed. On some
cameras it adds geometry rather than texture; the panel says which.

It caps at ~1024 px, so combining it with **Render at document resolution**
yields a layer that has to be upscaled several times over — which destroys the
fine texture that is its whole point. The panel warns and quotes the factor
before you spend the time. Use one or the other.

## Resolution

Two resolutions, deliberately split:

- **Scene understanding** (depth, matte, materials, saliency) always runs at
  1280 px. Its models do not scale and its output is smooth and semantic, so the
  channels are lifted to the render resolution with a guided filter using the
  full-resolution source as guide — edges come from the real image, not from
  interpolation.
- **Physics, sensor and art direction** run at whatever **Render at document
  resolution** selects: 1280 px when off (fast, for finding the look), the
  document's own long side when on.

Cost is ~1.4 s per megapixel on an M1 Ultra, so a 20 MP render is ~30 s. The
panel quotes the estimate before you commit to it. A selection render is sharper
than a full-canvas one at the same setting, because the selection's native pixels
cover fewer of them.

## UXP notes

Things that cost time to discover, kept here so they are not rediscovered:

- **`network` permission must be `"domains": "all"`.** Host/port entries such as
  `http://127.0.0.1:8077` match nothing and fail with *"Permission denied …
  Manifest entry not found"*. A fixed list also cannot support a user-set port.
- **`sp-slider` ignores a `label` attribute.** Dial names are plain DOM text.
- **`placeEvent` centres what it places and sizes it to the canvas**, and the
  service returns working-resolution pixels, so an imported layer is almost never
  the size of the region it belongs to. Measure the placed layer's actual bounds,
  scale to the target, then translate — translating alone parks a canvas-sized
  layer at the target's origin.
- **Cropping cannot preserve a selection's shape**, only its bounding box. Stash
  the live selection in an alpha channel and apply it as a mask afterwards.
- **UXP's FormData is unreliable** — the panel POSTs raw bytes to
  `/api/upload-raw`, which sniffs magic bytes instead of trusting a filename.
- Panels need `overflow-y: scroll`; with `auto` the scrollbar reads as absent.
- Photoshop mutations must run inside `core.executeAsModal`. Network waits are
  kept outside it so Photoshop's UI is not held hostage during downloads.
